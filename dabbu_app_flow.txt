1. APP ARCHITECTURE OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Tech Stack:
  • Framework: React Native (Expo SDK 50)
  • Navigation: @react-navigation (native-stack, bottom-tabs)
  • State: React Context (AuthContext, ThemeProvider, PreferencesContext, etc.)
  • Styling: StyleSheet + theme system (light/dark/couple mode)
  • Icons: @expo/vector-icons (AntDesign, Ionicons)
  • Fonts: Inter (Google Fonts via expo-font)
  • Storage: expo-secure-store (tokens), AsyncStorage (cache/prefs)
  • Backend: NestJS + Prisma + MySQL + Redis

Directory Structure:
  apps/mobile/src/
    ├── screens/          → 31 subdirectories, ~150 screen files
    ├── navigation/       → 12 navigator files
    ├── components/       → Reusable UI components
    ├── theme/            → Colors, typography, design tokens
    ├── store/            → Context providers (Auth, Preferences, Lock, etc.)
    ├── services/         → API client, preload, features config
    ├── hooks/            → Custom hooks (useCoupleMode, etc.)
    └── config/           → API config, category icons, features

Key Files:
  • App.tsx               → Root component, providers, deep links
  • RootNavigator.tsx     → Auth gatekeeper (phase machine)
  • MainTabNavigator.tsx   → Bottom tab bar + all 5 tab stacks
  • AuthContext.tsx       → Login, register, logout, token refresh
  • api.ts               → HTTP client, caching, offline queue, auto-refresh
  • ThemeProvider.tsx     → Light/dark/couple mode theme engine

═══════════════════════════════════════════════════════════════
2A. COLD START (App Launch)
═══════════════════════════════════════════════════════════════

The app launches with an animated SplashScreen showing the Dabbu logo.
In parallel, RootNavigator runs a phase state machine:

  Phase: 'loading'
    → Shows <SplashScreen> (animated logo + tagline, ~3 seconds)
    → During splash, these happen in parallel:
        1. GET /admin/maintenance  → checks if backend is in maintenance mode
        2. AuthContext.loadStoredAuth()  → reads saved tokens from SecureStore
        3. Features config loads, fonts load (Inter 400/500/600/700)

  If maintenance mode → shows <MaintenanceScreen> (blocks everything)

  If no saved token:
    → phase = 'auth'
    → <AuthNavigator> renders

═══════════════════════════════════════════════════════════════
2B. ONBOARDING (First Launch Only)
═══════════════════════════════════════════════════════════════

  AuthNavigator checks AsyncStorage 'hasSeenOnboarding':
    → If NOT seen: shows OnboardingScreen (3 slides)
        Slide 1: "Track Every Rupee"
        Slide 2: "Build Wealth Together" (couples focus)
        Slide 3: "Split Payments Easily"
        → User can Skip anytime
        → On finish: AsyncStorage.setItem('hasSeenOnboarding', 'true')
        → navigation.replace('Login')
    → If already seen: shows Login screen directly

═══════════════════════════════════════════════════════════════
2C. LOGIN / SIGNUP
═══════════════════════════════════════════════════════════════

  ┌─ Login Screen (PremiumLoginScreen) ──────────────────────┐
  │  • Email + Password fields (pre-filled with demo creds)  │
  │  • "Let's Start" button → POST /auth/login               │
  │  • "Create one" link → navigates to Signup               │
  │  • Google Sign-In button → OAuth → POST /auth/google     │
  │  • Demo Login button → POST /auth/demo                   │
  │  • Forgot Password? → navigates to ForgotPassword        │
  └──────────────────────────────────────────────────────────┘

  ┌─ Signup Screen (PremiumSignupScreen) ────────────────────┐
  │  • First Name, Last Name, Email, Phone, Password          │
  │  • Optional: Referral Code                                │
  │  • "Create Account" → POST /auth/register                 │
  │  • Google Sign-In fallback                                │
  └──────────────────────────────────────────────────────────┘

  On successful auth (any method):
    → Server returns { user, tokens: { accessToken, refreshToken, sessionId } }
    → applyAuth():
        1. setAccessToken(token) → warms up backend + starts keep-alive
        2. Save to SecureStore: accessToken, refreshToken, sessionId
        3. Save userData (JSON) to SecureStore
        4. Start 24-hour session timeout timer
        5. Refresh premium status in background

═══════════════════════════════════════════════════════════════
2D. SESSION VALIDATION
═══════════════════════════════════════════════════════════════

  After auth, RootNavigator sets phase = 'validating'
    → Shows "Verifying your session..." spinner
    → GET /auth/profile with Bearer token

  Possible outcomes:
    • 401 response → session expired → logout() → back to auth
    • Success (or other error, allowing grace) →
        - If app lock enabled: phase = 'lock' → <AppLockScreen> (PIN/biometric)
        - If isNewUser: phase = 'setup' → <ProfileSetupScreen>
        - If needsPhone: → <PhoneScreen>
        - Otherwise: phase = 'app' → <MainTabNavigator>

═══════════════════════════════════════════════════════════════
2E. NEW USER SETUP
═══════════════════════════════════════════════════════════════

  ProfileSetupScreen:
    → Edit First Name, Last Name, Phone
    → PATCH /users/profile
    → completeProfileSetup() → sets isNewUser = false

  PhoneScreen (if user has no phone):
    → Enter phone number with country code
    → PATCH /users/profile { phone }
    → Proceed to main app

═══════════════════════════════════════════════════════════════
2F. APP LOCK
═══════════════════════════════════════════════════════════════

  AppLockScreen:
    → On mount: tries biometric auth automatically if enrolled
    → User enters 4-digit PIN via custom keypad
    → PIN verified against SecureStore 'appPin'
    → "Forgot PIN?" → triggers logout
    → On success → unlockApp() → proceed to main app

  Lock triggers when:
    - App goes to background and returns
    - SecureStore has both 'appPin' and 'appLockEnabled'

═══════════════════════════════════════════════════════════════
2G. DURING APP USAGE (Token Lifecycle)
═══════════════════════════════════════════════════════════════

  • Every API call auto-attaches Bearer token via interceptors
  • Before each request: JWT 'exp' claim is checked (30s buffer)
  • If token expired → auto-refresh via POST /auth/refresh
  • Every 4 minutes: GET /health keep-alive (prevents server-side expiry)
  • If 401 received:
      → First retry with same token
      → If still 401 → refresh token
      → If refresh fails → session expired → logout()
  • 24-hour absolute session timeout (resets on activity)
  • Returns from background: LockContext checks PIN status

═══════════════════════════════════════════════════════════════
2H. LOGOUT
═══════════════════════════════════════════════════════════════

  User taps Sign Out (in Settings):
    → Confirmation dialog
    → logout():
        1. POST /auth/logout (fire-and-forget)
        2. Clear session timeout
        3. Delete from SecureStore:
           accessToken, refreshToken, sessionId, userData,
           appPin, appLockEnabled, biometricEnabled
        4. Clear AsyncStorage:
           preferences, contacts, offline queue, couple mode, cache
        5. setAccessToken(null) → stops keep-alive
        6. clearCache() → wipes all API cache
        7. Reset state: isAuthenticated = false
    → RootNavigator sees isAuthenticated = false → phase = 'auth'
    → User sees Login screen again

4K. OFFLINE SUPPORT
═══════════════════════════════════════════════════════════════

  The app queues mutations when offline:
    • When device goes offline → mutations saved to offlineQueue
    • When connectivity returns → queued mutations replayed in order
    • GET requests use stale cache when offline
    • OfflineBanner component shows "You're offline" at the top
    • Uses NetInfo from @react-native-community/netinfo

5. THEME SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Modes: light | dark | system (follows device setting)
  Stored in AsyncStorage: @dabbu_theme_mode

  4 Color Palettes:
    • palette.light       → Violet accent (#7C3AED), white/light backgrounds
    • palette.dark        → Violet accent (#A78BFA), dark backgrounds
    • palette.coupleLight → Rose accent (#F43F5E), pink-tinted backgrounds
    • palette.coupleDark  → Rose accent (#FB7185), dark pink backgrounds

  Couple Mode determines which palette is active:
    • When user.isCouple && user.isCoupleMode → uses couple palette
    • Otherwise → uses standard palette

  Theme object (useTheme() hook):
    • dark: boolean
    • colors: ColorPalette (bg, text, accent, border, status, etc.)
    • typography: font sizes & weights (Inter, Apple SF naming)
    • spacing: 8pt grid (xs=4, sm=8, md=12, lg=16, xl=20, ...)
    • borderRadius: sm=6, md=8, lg=10, xl=12, 2xl=16, 3xl=20, ...
    • isDark: boolean
    • mode: 'light' | 'dark' | 'system'

6. API & DATA LAYER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Base URL: Configurable via app.json extra.apiUrl or EXPO_PUBLIC_API_URL
  Default: https://dabbu-1ff9.onrender.com/api/v1

  API Client (api.ts):
    • Wraps fetch with: auth headers, caching, offline queue, retry, timeout
    • Methods: api.get(), api.post(), api.put(), api.patch(), api.delete()
    • Caching: in-memory + AsyncStorage, per-endpoint TTL, stale-while-revalidate
    • Offline: queues mutations, replays when online
    • Deduplication: concurrent identical GETs share one request
    • Auto-refresh: 401 → refresh token → retry
    • Loading tracking: global counter for ApiProgressBar

  Key Backend Modules:
    • Auth: login, register, google, demo, guest, refresh, logout
    • Users: profile, UPI validation, preferences
    • Accounts: CRUD, stats
    • Transactions: CRUD, stats, monthly report, PDF/Excel export
    • Categories: list
    • Budgets: CRUD
    • Goals: CRUD, contribute
    • Shared Finance: groups, expenses, settlements, members, invites
    • Couple: dashboard, requests, planners, timeline, coach, gamification
    • Household: bills, contributions
    • AI: insights, DNA, coaching, anomaly detection
    • Notifications: push, preferences
    • Referrals: codes, earnings
