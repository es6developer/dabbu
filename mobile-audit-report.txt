  File: apps/mobile/src/screens/dashboard/DashboardRouterScreen.tsx

  File: apps/mobile/src/screens/transactions/MyWalletScreen.tsx

  No transaction data is ever loaded.

  File: apps/mobile/src/screens/transactions/TransactionsList.tsx

  transactions forever.

8. ARCHITECTURAL ISSUES
================================================================================

8.1 FormField Naming Conflict
  Two components named FormField exist:
    components/ui/FormField.tsx
    components/forms/FormField.tsx (exported as FormField + FormFieldNew)
  This can cause import confusion and unpredictable behavior.

8.2 Tailwind + StyleSheet Hybrid
  nds/ components use className (Tailwind/NativeWind), while the rest of the
  app uses StyleSheet.create. This creates style inconsistency and potential
  rendering differences.

8.3 No RevenueCat / IAP Integration
  PremiumContext has 'mock' restorePurchases. There's no actual App Store or
  Play Store in-app purchase integration wired. Premium features cannot be
  purchased in the current build.

8.4 SMS Parsing is Android-Only
  sms/sms-parser.ts has native module dependency for Android only. No iOS
  implementation exists.

8.5 Duplicate Widget Implementations
  Some widgets exist BOTH in:
    components/dashboard/ (standalone)
    components/dashboard/widgets/ (registry-based)
  WidgetRegistry imports from widgets/, while DashboardGrid imports from the
  root dashboard components directory.

8.6 accessToken Pattern Inefficiency
  ~19 screens repeat this unnecessary pattern before API calls:
    if (accessToken) { setAccessToken(accessToken); }
  This is an async state update that accomplishes nothing.

8.7 Missing Loading/Error States
  ~25+ screens call api.get/post but lack proper loading, error, or empty
  state UI components.
